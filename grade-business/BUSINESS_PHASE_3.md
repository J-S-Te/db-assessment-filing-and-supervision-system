# 整改闭环开发目标

从已通过的整改规划生成逐项隐患台账。经办人上传整改证据并提交复核。复核可退回补正或销项，时间线保留责任人、期限和操作记录。工作台按最新状态显示待审核规划、待复核隐患、临期和逾期，支持直达记录。

- [x] 修复整改材料关联竞争。上传带当前页面的测评报告标识，服务端在计划行锁中核对。旧页面上传被拒绝时不登记或保留文件。
- [x] 实现隐患台账。审批和台账生成同事务提交。已批准的历史规划可手动同步，按规划与风险项序号保持幂等。台账记录保留规划、报告、备案关联。
- [x] 实现证据和复核。待整改或退回的风险项可上传证据并提交，退回时保留原因和证据，复核销项后保留来源、证据及时间线。
- [x] 接入工作台。保留既有待初审入口，新增真实统计和整改待办。期限口径采用中国时区，周期为当天起十日，销项后退出待办和临期统计。
- [x] 统一接口与构建验收。使用隔离 PostgreSQL 和生产前端构建验证自动及重复同步、旧页面冲突、退回再提交、销项、附件归属和工作台变化。旧本地实例保留独立资源。
- [x] 浏览器交互验收。Chrome 完成两次证据上传、提交复核、退回、补正重提及销项。确认仅有旧证据时重提被拒绝，销项后证据可下载且待复核、逾期计数归零。
