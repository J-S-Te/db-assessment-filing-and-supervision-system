# 机构材料失败恢复与异常预警

## 本地入口

- 隔离预览 `http://127.0.0.1:18464/`，任务标签 `local.ai-agent.grade-business-material-recovery`。使用专用 PostgreSQL schema、附件目录与前端构建。
- [机构未成功报告](http://127.0.0.1:18464/institution/reports?view=failed)、[机构材料异常](http://127.0.0.1:18464/institution/alerts?view=materials)、[运营者材料异常](http://127.0.0.1:18464/operator/alerts?view=materials)、[监管材料异常](http://127.0.0.1:18464/alerts?view=materials)。本地测试通过页面选择业务范围。

## 业务规则

- 机构备案支持独立材料和 ZIP 包。ZIP 核对备案表、定级报告两个现有必传类别，校验成功后登记原始 ZIP，原有单文件流程继续可用。原型提及十类标准命名，仓库目前能确认两类必传材料。
- 材料异常以业务记录和类别为单位登记。内容或大小校验失败、以及服务端可识别业务类别的传输中断可形成异常。未关闭的同类异常只产生一条首次提醒。合格替代材料关闭该异常，监管可以核对原原因、时间和处理结果。仍有未关闭异常时，机构须先补正再送审。
- 机构从测评报告「未成功」重传材料或删除从未提交的报告草稿。删除保留异常与送达留痕，已有审核留痕的报告只允许按原流程补正。
- 三端从预警页面查异常，机构与运营者继续使用站内消息收件箱。运营者看到本单位处理状态及必要说明。首次提醒和关闭通知分别与异常事务提交，前台定时或切回页面时刷新。材料有效期规则待明确。登录和 HTTPS 暂缓。

## 实施与验证

1. 在既有上传入口登记失败、处理上传幂等，在材料事务内完成补正关闭。测试范围涵盖归属、同时重试和撤销与送审竞争。
2. 加入验证后的备案 ZIP 类别，并在提交时按同一材料门禁核对。测试损坏件、不合规目录和必传成员。
3. 接通三端异常列表与通知跳转，机构失败列表支持选择本地替代文件并提交、删除未送审草稿。
4. 在隔离 PostgreSQL 上执行 Go 全包竞态、静态检查、构建和接口验收，在浏览器联验三端页面。

## 接口与浏览器验收

- OpenAPI 1.18.0，迁移 036。接口文档校验覆盖 235 个唯一操作与 672 个本地引用。
- 隔离 PostgreSQL 上 Go 全包竞态测试、`go vet ./...` 和后端构建通过，语句覆盖率 79.6%。Vue 类型检查、14 项单测和生产构建通过。
- 2 组新增和 42 组既有真实 HTTP 验收通过。覆盖 ZIP 缺项、备案规则预审、上传中断、并发重发、提醒去重、草稿按状态删除及三端同步。
- Chrome 实际完成 ZIP 缺项、补传和送审，报告失败后通过收件通知查看异常并从「未成功」重发，以及删除未送审草稿后监管查询关闭原因。核对了运营者显示的关闭状态和文件名范围。
