# 首次报送与整改规划实施计划

**目标**　三端使用同一份业务记录，机构端可以从草稿发起备案、变更注销、实施及测评报送，运营者可以首次提交整改规划，监管端沿用既有审核流程。

**技术范围**　Vue 3、Go net/http、pgx、PostgreSQL 和本地归属选择。登录和 HTTPS 按本轮约定留到后续。

- [x] 机构备案、变更注销与测评共用现有数据及审核处理。九类报告材料用数据库和提交事务校验，旧记录继续按原提交规则处理。
- [x] 机构实施可以筛选本机构有效备案、保存和提交报备，现有配额、撤回和监管审核规则继续在后端生效。
- [x] 运营者整改可以从本单位合格报告编制草稿。监管端与运营者端的提交共用同备案在审约束，退回、撤回、通过可释放名额，已提交动作保留历史。
- [x] 前端提供首次报送、我的记录、草稿继续、补正和审核意见入口。三端从相同业务接口读取服务端状态，页面切回时刷新。
- [x] 开发完成后统一运行 Go 全包竞态、覆盖率、静态检查、前端构建和隔离实库验收。验收包含缺失材料、跨归属、并发提交、消息回执和三端状态变化。

## 实施口径

- 机构首次备案沿用备案表、定级报告两类必传。关联变更注销、实施或测评时选择本机构的有效备案。
- 机构新报测评固定九类材料配置。报告文件、整改规划、等级测评结论、主要安全问题及整改建议、封面与基本信息表及声明为前五类必传。
  存量报告继续按原材料规则提交。新报告从监管端提交或补正重提时仍使用原配置。
- 运营者首次提交使用该备案最新通过的测评报告。整改规划方案、责任分工表和实施计划表必传，高风险项证据选传。
  历史退回的规划继续关联原报告。撤回后原规划保留终态、材料和审核留痕。
- 监管与运营者入口共同受数据库的备案在审占位约束。历史重复在审记录原样迁移，最后一笔退出在审后才能新增。
- 正式账号接入前，测试通过 URL 上的所选机构或单位确定业务范围。公开接口仍通过本机回环服务使用。

## 统一验收

独立 PostgreSQL schema、本地材料目录和 `http://127.0.0.1:18456/`。OpenAPI 1.11.0，新增迁移 020、021。

| 核验 | 结果 |
| --- | --- |
| `go test -race -count=1 -coverpkg=./... -coverprofile=<临时文件> ./...`、`go vet ./...`、`go build ./cmd/manager` | 全包通过，语句覆盖率 77.5% |
| Vue 类型检查、Node 单测、Vite 生产构建 | 通过，前端单测 5 项 |
| `tests/first_submission.py`、`tests/acceptance.py` | 6 组首次报送与 19 组原业务接口回归通过 |
| Chrome 机构首次备案 | 新建草稿、逐类上传备案表和定级报告、提交后机构及监管均显示待初审 |
| Chrome 运营者首次整改 | 选报告并创建草稿、上传三类必传、提交；监管审核通过并显示隐患台账，原运营者页面切回自动同步为已通过 |

源码复核修复了注销标记、返回路由和已有申请筛选。旧报告超过详情附件上限时保留报告正文，新增隔离数据库回归用例。
