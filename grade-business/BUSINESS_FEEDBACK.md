# 测评审核意见回传

目标是完成测评报告的本地回传链路。监管端退回补正或通过终审时生成站内意见，机构可按测评机构名称收取并签收。被退回的报告可在机构办理页补传材料并重新提交，监管端可核对签收记录和当前审核状态。

- [x] 审核状态、留痕和送达消息在同一事务写入。一次审核事件对每家接收机构保留一条消息，记录接收机构、报告编号和系统名称。新审核开始记录回传。改派仍待补正的报告会向新机构送达当前意见，原机构的签收记录继续保留。
- [x] 已接通有界收件箱、幂等签收、材料上传下载和重新提交。机构范围在读取及持锁写入时核对。重提使用原有材料规则、版本检查和审核状态机。
- [x] 机构端提供回传列表和补正入口，监管端在「测评详情 → 审核留痕 → 机构回执」显示送达和签收时间。机构列表和报告、监管测评详情及回执在前台每 10 秒读取，页面切回时刷新。
- [x] 在独立 PostgreSQL schema 验证退回、重提、终审、接收范围、并发重复签收、报告改派与回传失败同事务回滚。OpenAPI 1.5.0、Go 全包竞态和前端构建通过。

当前应用仅供回环测试。机构名称用于本地业务范围筛选，正式接收人身份需由机构账号提供。此轮站内回传通过本地业务数据库持久化。

## 浏览器验收

测试版运行在 `http://127.0.0.1:18451/`。进入机构端后，可用「跨端浏览器验收机构」查询已验证的报告 `QA-RECEIPT-116c1016b0`。

Chrome 中，监管端退回后在机构收件箱确认签收、上传合成 PDF 并提交初审。切回原监管页面后看到重提状态、审核留痕和第一次回执。完成初审和终审后，机构端签收终审结果。监管端两条回执均显示已签收。另从接口核对了两次签收的持久化时间、五条审核状态记录及新附件下载内容。
