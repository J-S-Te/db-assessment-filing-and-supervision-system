# M8 AI 智能审核接入

本期把管理端 M8 从“待接入”改为同源 `/review/` 页面，复用现有 `grade_business_session`、首登改密、账号启停与监管辖区过滤，不使用 DBReportReviewer 的本地登录或用户表。原平台是身份及报告归属的唯一来源，没有账号复制、跨系统密码传递或客户端角色断言。

## 范围及运行

用户已明确授权：`ROLE_SYS_ADMIN` 和 `ROLE_REGULATOR` 可访问 M8；机构、运营者、未知角色不新增权限。`GET /review`、`GET /review/` 和固定静态资源全部经过 `access.Protect`；未登录返回原 `/login?redirect=/review/`，首登未改密返回原改密页。`GET /api/v1/ai-review/context` 同样经过该网关，返回服务器当前会话视图。伪造 X-User-ID、X-Role 不产生身份。页面只读，采用原 `/api/v1/reports`、详情和附件接口，每次读取仍由原平台检查范围；监管员不能从 M8 串读其他辖区。

独立审核源码位于同级 `DBReportReview-web` 的 `integrated.html`、`review-platform.mjs`；平台只承载构建产物。部署时不指向 `index.html` 合成原型，也不跳转 `portal.html` 的第二套本地账户。返回原平台办理继续使用已有审核权限和流程。完整前端提供工作台、报告管理、报告接入、执行、结果、问题证据、复核、规则依据、记录及权限十个页面。报告、材料、办理记录和知识库读取原接口；AI 任务及结果工件尚未接入，相关区域明确保持未启用或待获取，不将办理状态当作 AI 结论。

在平台前端构建前生成发布包：

```sh
node ./DBReportReview-web/tools/package-platform-review.mjs \
  ./db-assessment-filing-and-supervision-system/grade-business/web/public/review
```

上述相对路径示例从三仓库共同父目录执行，或直接使用绝对路径。脚本只打包六个固定资源和摘要清单，拒绝覆盖非本工具生成的现有目录；生成的 `web/public/review/` 被 Git 忽略。随后按平台原有步骤构建 `web/dist`、启动 manager。Node、Vue、数据库与 Cookie 均沿用现有组件，不添加身份依赖或数据库迁移。只用静态 HTTP 服务不能模拟真实平台会话。

## 测试服发布

现有 GitHub Actions 的镜像 job 从本平台仓库的 Release 下载最小静态发布包，不跨仓库检出私有源码。平台仓库变量 `AI_REVIEW_WEB_REF` 必须是 `J-S-Te/DBReportReview-web` 中已验证的完整 40 位提交 SHA，`AI_REVIEW_WEB_BUNDLE_SHA256` 必须是对应归档的完整 SHA-256。发布标签为 `ai-review-web-<前端提交 SHA>`，附件为 `ai-review-web.tar.gz`。流水线拒绝缺失或格式错误的变量，下载后先核验归档摘要，再解压到 `web/public/review` 并构建原镜像。回滚使用原流水线的上一镜像；没有数据库迁移或线上用户授权批量修改。

私有前端提交的六个静态资源和 `.review-bundle.json` 由打包工具生成，归档不包含账号、运行配置、测试、原型或私有仓库其余源码。公开平台的 Release 附件可公开下载，用户已明确授权公开本次最小静态包。前端升级时先在私有仓库测试并提交，再打包、核对文件范围和摘要、发布对应附件，更新两项平台变量后触发原流水线。原前端测试在发布归档前执行；CI 负责平台完整测试、发布摘要验证及镜像部署。
