# 管理端 V2 业务流核对

以[功能清单](../软件开发功能清单（原型基线版）.md)和[管理端原型 V2](../原型/管理端/index.html)为目标，按当前源码、接口和本地回归确认实现进度。

| 业务 | 当前本地实现 | 仍需完成 |
| --- | --- | --- |
| 备案、变更与注销 | 管理端录入、机构首次报送、运营者自主首报与变更注销、材料校验、跨端回执和退回补正。监管可预检历史 ZIP 并导入草稿。机构可复制备案为新草稿、批量删除未送审草稿和送审。机构备案 ZIP 校验备案表和定级报告。运营者首报、变更或注销在审可请求监管确认撤回，确认后释放占用。换机构变更先核对通过的复测报备。 | 原型其余标准材料的分类、命名和必传规则，以及模型抽取。 |
| 实施报备 | 机构首报、运营者发起换机构复测报备、变更配额、撤销、两级审核、监管复核、退回补正与签收。通过后可归档。监管及当前发起方可核对报备字段、日期、备案材料、名录和额度，查看版本及有权访问的原件。 | 材料正文抽取和更多校验规则需明确材料格式与业务口径。 |
| 测评报告 | 机构首报九类材料与五类必传、报告未成功列表与重发、删除未送审草稿、两级审核、跨端回执、监管和机构各按范围筛选导出、DOCX、文本及扫描 PDF 抽取和人工校对，记录页码和来源。终审通过后监管按附件登记得分、结论和风险数量。运营者按交付与历史归属查询年度得分，下载可交付文件，查看和对比两期已批整改问题。合规可按题名和明确编号查找启用条款，也可人工选取，留痕固定证据、知识及条款版本。 | 既有报告的结论和正式条款待按原件录入。更多材料格式及正式机构身份绑定随相应业务接入。 |
| 整改规划与隐患 | 支持规划自动登记及监管直接登记，双台账按条件查询导出。重大风险支持派单和按日督办，运营者提交本轮证据，测评机构完成报告复测，监管复核销项。监管和运营者可下载整改方案、责任分工和实施计划参考模板。支持查进度和下载回执。 | 正式模板替换需核准样表。外部数据源自动接入。 |
| 工作台与提醒 | 三端按当前状态投影待办，报送者可在详情及业务时限查询正在其他端办理的期限。监管可配置补班、休息日和恢复默认，并按日期查变更和集中操作审计。临期、到期和超期站内提醒按阶段去重，运营者可按日催办复测。 | 按实际工作安排录入节假日和补班。新来源预警和站外投递渠道待接入。 |
| 知识库与智能体 | 条目录入、检索、CSV 预检与批量导入、历史快照、版本引用、统一标签目录。法规和标准支持按条款登记、修订和停用。 | PDF、Word 和 Markdown 直接批量入库。智能体会话、模型辅助语义比对及 DeepSeek Harness 接入。 |
| 全息档案 | 三端共用单位、机构资质和测评人员名录。已停用或过期主体退出新办理候选。复杂模式逐笔列出有效备案、在办事项、历史范围及阻塞原因，确认后移交符合约束的在办责任。系统可登记 IP、域名、拓扑关系、供应商、安全事件、云和大数据资产，有版本记录。供应商可维护统一主档并关联备案系统，拓扑图使用已登记连接。 | 未办结的审核或检查、已有证据或关联预警的隐患等按预览先办理。已归并过其他单位的主单位再次作为来源，仍需链式移交口径。正式资产、存量供应商绑定和覆盖清册待录入。 |
| 监测与发布 | 高风险和逾期隐患触发预警，运营者可转办、申请延期、反馈误报及按日期导出已关闭台账。机构处置反馈和材料补正同步关闭。三端查业务时限和材料有效期，监管可以分页筛选并下载正式原件后按依据登记。续传通过后结束旧预警。监管可预览及配置本地规则并追溯命中。公告支持定向发布、附件下载、签收和版本回执。运营者有独立的政策标准与常用资料视图。 | 待提供可核实的历史原件、截止日期和归属依据以补录实际记录。外部触发数据和站外推送待接入。 |
| 监督检查 | 监管可单笔下发年度自查、按区县和等级预览并批量下发、从真实超期线索发起检查。指定单位查任务和模板、上传材料，监管退回补正或办结。现场安排、结果、证据、跟进和办结保留原收件范围及办理留痕。现场跟进、监管复核同步工作台，按实际截止日投递临期、当日和逾期提醒。 | 外部检查数据接入。 |
| 驾驶舱与系统管理 | 指挥驾驶舱支持 16:9 全屏总览、7／14／30 日趋势、实时预警和业务下钻。备案覆盖率取自实际覆盖清册，资产分类型取自有效备案。可在本机导入区县边界查看真实未销项风险，按已登记行业和隐患分类查看行业风险和常见问题排行。系统管理提供操作审计和知识共享标签维护。 | 正式区县边界和存量行业、问题分类待录入。账号角色、登录日志、短信审计随正式接入推进。字段字典、机房和收藏配置待明确对应业务对象及管控规则。 |

## 状态、提醒与技术选择

- 各业务模块以服务端状态、版本和允许动作作为页面依据。已提交的审查动作使用行锁和版本校验。审核冲突时关闭旧确认窗口，刷新记录、材料和留痕，要求从新审核阶段重新发起确认。
- 隐患列表、工作台、详情和历史使用同一套状态名称。工作台通过只读可重复读事务读取待办与计数，顶栏共用响应。办理成功后主动刷新，前台每 30 秒补查，页面重新可见时也刷新。角标数字表示当前有事项的类别数，详情显示各类实际数量。
- 当前采用 Go `net/http`、`pgx` 和 PostgreSQL。现有模块依赖显式 SQL、事务和版本检查。后续采用 Gin 时可以按 HTTP 层独立评估。
